# Enable Navigation Icons - Development Guide

## Project Overview
WordPress plugin that adds icon support to Navigation Block items (navigation-link, navigation-submenu, ollie/mega-menu). Uses `@wordpress/scripts` for build tooling.

## Commands
- `npm run build` — Build for production (also regenerates `build/icon-manifest.php`)
- `npm run build:icon-manifest` — Regenerate the icon manifest only (requires a prior webpack build)
- `npm run start` — Watch mode for development
- `npm run lint:js` — Lint JavaScript
- `npm run lint:css` — Lint CSS/SCSS
- `npm run lint:js:src:fix` — Auto-fix JS lint issues
- `npm run plugin-zip` — Create distribution zip
- `npm run update-pot` — Generate translation POT file
- `npm run playground` — Launch WordPress Playground with plugin auto-mounted

## Block Attributes

### core/navigation (parent — default settings for all child items)
| Attribute | Type | Purpose |
|---|---|---|
| `defaultIconSize` | string | CSS value (e.g. `"24px"`) applied to all child icons |
| `defaultIconSpacing` | string | CSS gap between icon and text |
| `defaultCustomIconColor` | string | Hex/CSS color for all child icons |
| `defaultIconPositionLeft` | boolean | Show icons before text (default: false = right) |
| `defaultJustifySpaceBetween` | boolean | Space-between layout for icon + text |
| `defaultHasNoIconFill` | boolean | Stroke-only mode (for Lucide-style icons) |
| `defaultIconVerticalAlign` | string | `"top"`, `"center"` (default), or `"bottom"` |
| `defaultIconOffset` | string | CSS value for `top` offset (e.g. `"2px"`, `"-0.1em"`) |
| `defaultIconRotate` | number | Rotation in degrees applied to all child icons (default: 0) |

### core/navigation-link, core/navigation-submenu, ollie/mega-menu (per-item settings)
| Attribute | Type | Purpose |
|---|---|---|
| `icon` | string | Raw SVG string (custom or media library upload) |
| `iconName` | string | Icon identity. A bare slug (e.g. `wordpress-github`) for bundled icons, or a namespaced `collection/icon-name` (e.g. `core/plus`) for WordPress Icon API icons |
| `iconColor` | string | Theme palette color slug |
| `customIconColor` | string | Arbitrary hex/CSS color |
| `iconPositionLeft` | boolean | Override default: show icon on left |
| `justifySpaceBetween` | boolean | Override default: space-between layout |
| `hasNoIconFill` | boolean | Override default: stroke-only mode |
| `iconSize` | string | Override default: CSS icon size |
| `iconSpacing` | string | Override default: CSS gap |
| `iconVerticalAlign` | string | Override default: `"top"`, `"center"`, `"bottom"` |
| `iconOffset` | string | Override default: CSS `top` offset |
| `iconRotate` | number | Override default: rotation in degrees |
| `useDefaultIconSettings` | boolean | When true (default), inherits parent Navigation block settings |

## PHP Hooks & Filters (enable-navigation-icons.php)

| Hook | Type | Priority | Purpose |
|---|---|---|---|
| `enqueue_block_editor_assets` | action | default | Enqueue editor JS (`build/index.js`) |
| `enqueue_block_assets` | action | default | Enqueue editor CSS (`build/editor.css`) — admin only |
| `init` | action | default | Register block styles for navigation-link, navigation-submenu, ollie/mega-menu |
| `init` | action | 11 | Publish bundled icons to the WordPress Icon API (7.1+); after core's own registration at priority 0/10 |
| `render_block_core/navigation-link` | filter | 10 | Inject icon HTML into rendered frontend output |
| `render_block_core/navigation-submenu` | filter | 10 | Same as above for submenus |
| `render_block_ollie/mega-menu` | filter | 10 | Same for Ollie mega menu items |
| `render_block_data` | filter | 5 | Capture Navigation block attrs onto the global stack before child blocks render |
| `render_block_core/navigation` | filter | 1000 | Pop Navigation block attrs off the stack after all children have rendered |

## JavaScript Filters (src/index.js)

| Filter | Purpose |
|---|---|
| `blocks.registerBlockType` | Add icon attributes to supported blocks |
| `editor.BlockEdit` | Inject toolbar button + Inspector Controls into navigation items and the Navigation block |
| `editor.BlockListBlock` | Add CSS classes and inject `useStyleOverride` CSS for editor-side icon preview |
| `iconBlock.icons` (consumed) | Third-party icon sets registered by the Icon Block plugin are automatically picked up |
| `iconBlock.enableCustomIcons` (consumed) | Allows Icon Block plugin to disable the custom SVG paste option |

## CSS Class Conventions (applied to the `<li>` in rendered HTML)

| Class | Condition |
|---|---|
| `has-icon__<iconName>` | Icon set from library (e.g. `has-icon__wordpress-github`). Slashes in namespaced Icon API names become hyphens, so `core/plus` yields `has-icon__core-plus` |
| `has-icon__custom` | Custom SVG icon with no name |
| `has-icon-position__left` | Icon positioned before text |
| `has-justified-space-between` | Space-between flex layout |
| `has-no-icon-fill` | Stroke-only rendering |
| `has-icon-align__top` | Vertical align top |
| `has-icon-align__bottom` | Vertical align bottom |

The icon `<span>` uses class `wp-block-navigation-item__icon` and is injected inside the first element with class `wp-block-navigation-item__content` (either `<a>` or `<button>`).

## Icon Registry

Icons are organized into two groups in `src/icons/index.js`:
- **Social icons** (`wordpressSocialIcons`): ~45 brand/social SVGs (custom SVGs in `src/icons/wordpress/social/`)
- **WordPress icons** (`wordpressIcons`): ~200 icons sourced from `@wordpress/icons` package

Both groups are combined into a single `icons` array with type `"wordpress"` and exported via `getIcons()`, which applies the `iconBlock.icons` filter to allow third-party additions.

To add a new built-in icon: add the SVG file to `src/icons/wordpress/social/`, export it from `src/icons/wordpress/social/index.js`, import and add it to the `wordpressSocialIcons` array in `src/icons/index.js`.

Icons not yet in the `@wordpress/icons` npm package go in `src/icons/wordpress/temp.js` until the package is updated.

## Development Standards
- Follow WordPress Coding Standards (WPCS) for PHP, JS, and CSS
- PHP 7.4+ minimum, WordPress 6.3+ minimum
- All user-facing strings must use `__()` / `_e()` with text domain `enable-navigation-icons`
- Sanitize all input (`sanitize_*`), escape all output (`esc_*`)
- SVG content must be sanitized with `wp_kses()` using the allowed tags list in the main PHP file

## Deployment
- **Git** is for development; **SVN** is for WordPress.org distribution
- GitHub releases trigger the deploy workflow (`.github/workflows/deploy.yml`)
- The `.distignore` file controls what's excluded from the distribution
- Version must be synced in: `package.json`, `enable-navigation-icons.php` (Version header), and `readme.txt` (Stable tag + changelog)
- CI uses `npm install` (not `npm ci`) due to npm version incompatibility between local (npm 11) and GitHub runners (npm 10)

## Key Architecture Notes
- Icons are rendered server-side via `render_block` filters — **not saved in block markup**
- REST API requests are skipped (`REST_REQUEST` constant check) to prevent icon HTML from being saved to post content when the editor auto-saves
- Parent Navigation block defaults use a global PHP stack (`$enable_navigation_icons_nav_stack`) — pushed on `render_block_data` (priority 5, before children render) and popped on `render_block_core/navigation` (priority 1000, after all children)
- Editor-side icon preview uses `useStyleOverride()` to inject CSS into the iframed editor — no direct `document` access
- Icon vertical alignment (`top`/`center`/`bottom`) is applied via `align-items` CSS classes on the `<li>` flex container
- Icon vertical offset uses `position: relative; top:` on the icon `<span>` — independent of alignment
- `blueprint.json` supports both hosted Playground (installs from WordPress.org) and local dev (`--auto-mount`). Pinned to `wp: nightly` so the 7.1 Icon API is available

## WordPress Icon API Integration (WordPress 7.1+)

The plugin both **consumes** and **publishes** to core's SVG Icon API, guarded throughout by `enable_navigation_icons_has_icon_api()` so 6.3–7.0 behave exactly as before.

- **Consuming**: `useCoreIcons()` fetches `/wp/v2/icon-collections` and `/wp/v2/icons` once per editor session and exposes each collection as an extra inserter type. Note that `WP_REST_Icons_Controller::get_items()` **ignores `page`/`per_page`** and returns the full set in one response — do not paginate it, or every icon will be duplicated.
- **Storage**: all library picks store only `iconName` with an empty `icon` attribute. Bundled icons store `enable-navigation-icons/<name>` — resolved from the shipped `build/icon-manifest.php` on the server and the bundled JS registry in the editor, so they render on WordPress 6.3+ with **no Icon API needed**. Core/third-party collection picks store their registry name, resolved by `wp_get_icon( $name, [ 'size' => null ] )` (7.1+). Third-party JS icon sets (`iconBlock.icons` filter) are not in the manifest and still embed raw SVG. Legacy content keeps its raw SVG in the `icon` attribute, which takes precedence.
- **Name normalization**: `src/utils/normalize-icon-name.js` maps JS registry names to manifest names (`wordpress-starFilled` → `wordpress-star-filled`). It is shared by the manifest build and the editor pick flow and MUST stay identical between them; shipped names are public API — never change normalization retroactively.
- **CSS class continuity**: the own-collection prefix is stripped from `has-icon__*` classes, so a 0.3.0 bundled pick produces the same `has-icon__wordpress-github` class as 0.2.x. Only foreign collections get namespaced classes (`has-icon__core-plus`).
- **No migration**: a slash in `iconName` is the discriminator between the two paths (`enable_navigation_icons_is_registry_icon()` / `isCoreIconName()`). Bundled names are always bare slugs, so old and new content can never be confused.
- **Sanitization**: registry markup is used as-is because core sanitizes it at registration and again in `wp_get_icon()`. Only legacy/custom SVG goes through the plugin's `wp_kses()` allowlist. Core's allowlist is narrower — `svg`, `path`, `polygon` only, with `stroke-*` stripped — so the manifest generator **converts `circle`/`rect` to exact `path` equivalents** and skips anything else it cannot represent (currently nothing; the build logs any future skips).
- **viewBox casing**: `wp_kses` lowercases `viewBox` to `viewbox`. Harmless in HTML (the parser case-corrects SVG attributes), but the editor preview embeds SVG in `mask-image` data URIs, which are parsed as case-sensitive XML — `svgToDataUri()` in `src/utils/icon-style.js` restores the casing. Don't remove that.
- **REST fetch gating**: `useCoreIcons( { enabled } )` only downloads the registry when the inserter modal is open or a block's `iconName` is registry-namespaced. The plugin's own collection is hidden from the inserter (duplicates the bundled set) but kept in the fetched data so previews can resolve `enable-navigation-icons/*` names.
- **Publishing**: `build/icon-manifest.php` is generated at build time and registered as the `enable-navigation-icons` collection. Registry names are normalized from camelCase to kebab-case (`starFilled` → `wordpress-star-filled`) and are **public API once released** — renaming them breaks stored content.
- **Presentation is source-agnostic**: size, spacing, color, position, alignment, offset and rotation are applied to the wrapper `<span>` and `<li>` classes, never to the SVG, so every control works identically for bundled, custom and registry icons.
